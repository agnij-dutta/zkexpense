# Contributing to zkExpense

Thanks for helping. zkExpense is a small codebase with three layers that must agree bit for bit: Noir circuits, the TypeScript prover/CLI, and the Solidity attestation contract. Most of this guide is about keeping them in sync.

## Dev setup

Prerequisites (exact versions matter: the verification keys and Solidity verifiers are generated by them):

| tool              | version                | install                                                                                                                 |
| ----------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Node.js           | 22 or newer            | https://nodejs.org                                                                                                      |
| nargo             | 1.0.0-beta.19          | `curl -L https://raw.githubusercontent.com/noir-lang/noirup/refs/heads/main/install \| bash && noirup -v 1.0.0-beta.19` |
| bb (Barretenberg) | 4.0.0-nightly.20260120 | `bbup -v 4.0.0-nightly.20260120`                                                                                        |
| Foundry           | 1.x                    | https://getfoundry.sh                                                                                                   |

```bash
git clone https://github.com/agnij-dutta/zkexpense && cd zkexpense
scripts/setup.sh        # npm install, TS build, forge deps, compile circuits, generate verifiers (~2 min)
```

## Test, lint, build

```bash
npm test                  # TS build + node tests (incl. real prove/verify) + nargo test + forge test
npm run test:ts           # node unit + end-to-end tests only
npm run test:circuits     # Noir tests (circuits/lib)
npm run test:contracts    # Foundry tests on real proofs
npm run test:adversarial  # slow (~1 min): substituted-circuit attack on the aggregator must fail

npm run lint              # ESLint (typescript-eslint strict), Prettier, nargo fmt --check, forge fmt --check
npm run format            # apply Prettier, nargo fmt, forge fmt
npm run typecheck         # tsc --noEmit
npm run build             # src/ -> dist/
npm run build:circuits    # compile circuits, write vks, pin inner vk hashes, regenerate Solidity verifiers
```

## Project layout

```
src/cli.ts            the `zkexpense` CLI (argument parsing and output only)
src/lib/types.ts      public types: Payment, PaymentLog, Policy, Report, ProofJson, Disclosure
src/lib/hash.ts       Poseidon2 sponge + Merkle helpers (mirror of the Noir hash)
src/lib/model.ts      log/vendor ingest and validation, leaf hash, salts, domain tags
src/lib/witness.ts    circuit inputs (Prover.toml) and the expected public inputs
src/lib/report.ts     proving pipeline: single batch or K batches + recursive aggregation
src/lib/toolchain.ts  thin wrapper over the nargo and bb CLIs
src/lib/verify.ts     verification (in-process bb.js, or bb CLI)
src/lib/disclose.ts   single-payment selective disclosure
src/lib/sample.ts     deterministic synthetic sample data
circuits/lib          the Noir library: hash, leaf, Merkle, prove_batch, aggregate, tests
circuits/batch_N      thin wrappers, N = 64 / 256 / 512 / 1024
circuits/agg_BxK      recursive aggregators, GENERATED by scripts/build.sh (pinned inner vk hash)
contracts/src         ExpenseAttestation.sol; verifiers/ is generated by bb
contracts/test        Foundry tests and real-proof fixtures
scripts/              setup, circuit build, fixture generation, benchmarks
test/                 node tests; test/adversarial holds slow attack tests
```

## Changing the circuits

Any change to `circuits/lib` changes the verification keys, so:

1. Mirror the change in TypeScript (`src/lib/hash.ts`, `model.ts`, `witness.ts`). `proveReport` compares every proof's public inputs with the TypeScript model and fails loudly on any mismatch.
2. `npm run build:circuits` to recompile, regenerate `agg_*` wrappers (new pinned vk hash) and the Solidity verifiers.
3. `npm run fixtures` to regenerate the real proofs the Foundry tests use, and `npm run bench` if the numbers in BENCHMARKS.md change.
4. Update "What is proven" in the README and add a Noir test for every new assertion (`#[test(should_fail_with = "...")]`).

## Adding a batch size or an aggregator

The extension point is the circuit list:

1. Batch size N: copy `circuits/batch_64` to `circuits/batch_N`, set `global N`, add N to `BATCHES` in `scripts/build.sh` and to `SINGLE_CIRCUITS` in `src/lib/circuits.ts`.
2. Aggregator over K batches of size B: add `"B:K"` to `AGGS` in `scripts/build.sh` and an entry to `AGG_CIRCUITS` in `src/lib/circuits.ts`. The wrapper is generated.
3. Run `npm run build:circuits`, register the new verifier in the contract tests, and add a benchmark case in `scripts/bench.mjs`.

## Adding an input format

Payment logs are normalized in `ingestLog` (`src/lib/model.ts`). A new source format (another x402 client, a facilitator export) belongs in `flattenX402` or a sibling function that maps it to the flat row `{ transaction, payer, payTo, amount, asset, network, timestamp }`. Add a test in `test/model.test.mjs`.

## Style

- TypeScript is strict; public functions get a doc comment that says why, not what.
- No em dashes in docs or comments.
- Small commits with plain messages.
